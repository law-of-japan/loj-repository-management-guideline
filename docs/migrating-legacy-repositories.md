# 従来の形式の既存のリポジトリを移すとき

従来の形式（このガイドラインの以前の版に従ったもの）の既存の法令リポジトリを、原典から作り直して新しい形式へ移すときに確かめてほしい規則です。参加する前に、[CONTRIBUTING.md](../CONTRIBUTING.md)を読んでください。

移行の手順は、[旧リポジトリから原典による再構築への移行の手順](https://github.com/law-of-japan/loj-spec/blob/main/docs/migration-from-legacy.md)を参照してください。既存の法令リポジトリの移行は、仕様の検査器ができてから始めます。検査器がないと、移したデータが仕様に適合することを確かめられないためです。

移した後の法令リポジトリのファイル構成と書き方は、新しく登録する法令と同じです（[法令リポジトリを作るとき](creating-a-repository.md#ファイル構成)、[本文・データを書くとき](writing-data.md)、[コミットし、マージするとき](committing-and-merging.md)）。ここには、既存のリポジトリに特有のことだけを書きます。

## 既存のリポジトリの名称

- 既存の法令リポジトリの名称は、凍結した後も変えません。旧リポジトリの名称を含むURL（`blob/master/…`等）による既存のリンクを保つためです（REB-08）。GitHubの改名の転送には頼りません。
- 既存の名称（`law.yaml`がある場合は`law.id`）を、そのままRecord IDとします（REB-02）。
- 既存の名称が日付や種別を含んでいても、Record IDから日付・種別を読み取ってはいけません（REB-02、MAN-01）。
- それより前に使っていた名称は、登録台帳のRecordの`aliases`に記録します。

参考として、既存のリポジトリの名称は以下の旧規則で付けられています。この規則で新しい名称を付けることはしません。

- 「YYYYMMDD-種別-番号」の形式で、YYYYMMDDは公布の日付、番号は法令番号等です。憲法のように法令番号がない場合は、YYYYMMDD-constitutionのように番号を書きません。
- 種別は、憲法がconstitution、法律がact、勅令がimperialOrder、政令がcabinetOrder、府省令がministerialOrdinance、規則がruleです。
- 府省令、規則等が細分される場合は「日付-種別-府省名等-番号」とし、府省名等のキーは、発令機関の一覧の各機関に該当するかどうかをビット列にし、36進数で表したものです（例: 19470830-ministerialOrdinance-B8JK-23）。キーを作るスクリプトと機関の一覧は、もう使わないため削除しました。発令機関は、登録台帳のRecordに原記載のまま記録します。

## 既存のリポジトリの`master`ブランチ

- 従来の形式の既存のリポジトリでは、規定のブランチ（`master`、または`main`）を、移行を始める時点で凍結します。凍結した旧履歴に、push・force pushしてはいけません（REB-08）。
- `blob/master/…`等の既存のリンクを壊さないように、旧`master`は残し、新しい正本は`main`ブランチに置きます。旧`master`が規定のブランチであれば、`main`を新しく作り、規定のブランチを`main`に切り替えます。
- 従来の`not_entered_into_force`ブランチ等、旧`master`以外の既存のブランチも、同様に凍結して残します。

## 旧本文を下書きにするとき

従来の形式の既存のリポジトリの本文（旧本文）も、下書きとしてだけ使えます。旧本文を版の本文の根拠にはせず、`text.sources`にも挙げません（REB-03）。旧本文を下書きにした版は、e-Govの本文を下書きにする場合と同じく、版ごとに原典資料と字ごとに照合して直し、照合したかどうかを`text.glyphCheck`に記録します。旧本文と原典の差は、再構築報告（rebuild.yaml）の`differences`に記録します（REBR-05）。改正後の版は、旧本文の改正後の全文から起こさず、基礎の版に改正の原典を当てはめて作ります（REB-03、REB-05）。

原典資料の選び方は、[原典資料](writing-data.md#原典資料)を参照してください。

## 従来のリンク

- 既存のリポジトリの旧コミットへのリンクや`blob/master/…`へのリンクは、固定参照ではありません（REB-08）。凍結して到達できるように残しますが、新しい記録版と同じものとして案内しないでください。
- 旧コミットに対応する版を案内するときは、再構築報告（rebuild.yaml）の旧コミットと版の対応を使って、Revision参照として案内します（REB-08）。

参照の形式は、[参照の書き方](writing-data.md#参照の書き方)を参照してください。
